# 农田作物放置与生成崩溃修复

用户已要求继续暂停的修复。本项回滚起点 `1c37fc6`，暂停时的完整诊断保存在 `docs/handoff/2026-10-16-farm-generation-crash-paused.md`。

## 问题和证据

报告 `crash-2026-10-16_02.52.54-server.txt` 的首个致命异常为 `Incomplete MCP component: farm`，由核心生成完毕后的逐块类型检查抛出。此前只读对照失败存档发现：农田253个非作物块全部匹配，110株作物中30株变空气（小麦12、胡萝卜18）。农田结构、耕地和水均存在，并非整个部件遗漏。

普通 `setBlock(...,2)` 仍触发邻居形状更新，而作物的存活判断依赖亮度。此前的施工顺序将种植与结构交错，光照刷新窗口内作物被移除最符合现有证据；保存后的天光15不能证明建造瞬间亮度，后者没有直接采样。本次针对该更新机制修复，没有再次读取或修改失败存档。

## 修改

1. 每栋先放置非作物方块；所有建筑、支撑、灌溉、围栏和道路完成后，最后统一放作物。
2. 只对最后的作物批量使用 `Block.UPDATE_CLIENTS | Block.UPDATE_KNOWN_SHAPE`（18），避免建造阶段的形状更新提前移除作物；其他方块仍保留正常形状更新，不影响门、围栏与楼梯的连接。
3. 六种建筑的完整规划、主屋床与出生点检查，以及非作物结构检查全部保留。结构缺失时错误补充坐标、预期与实际状态，便于精确定位。
4. 作物数量单独记录：`MCP crop placement farm: 110/110 present` 为全部种植时的预期日志；若植物仍发生变化，记录数量警告，不再把少量植物变化升级为服务器致命异常。

本次不改建筑源、选址、独立地坪、六部件要求或标准路线赠剑；不是删除全部完整性检查。

## 村民住宅

开发实例 `logs/latest.log` 的 01:32:13 记录证实，两栋村民住宅与水井被旧实现跳过，最终放置 3/6 个部件。旧日志没有分项拒绝原因，不能仅凭这条记录断言具体是哪一列地形或哪条路导致失败。

旧实现每个部件只检查设计位置附近的六处候选，不能充分避开某一侧的水岸、坡地或受保护区域。现在先保留这六处，再以玩家房屋为中心，在东、西、南、北和四个斜方向，按 20、32、44 格半径搜索，总数最多 30 处。两栋村民住宅各增加 9×9 占地的紧凑后备模板，普通与后备合计每栋最多 60 处；其他部件各最多 30 处。九点干燥地面预筛先排除明显水岸，后续仍逐列核查。

连接路按距离优先尝试已规划部件的入口，不再只尝试从玩家房屋接线。削高 6 格/补高 18 格、原生结构构件和方块实体保护、道路净空与级差限制保持有效。仍无法安全生成时按部件记录拒绝计数；不会为补齐房屋强行覆盖建筑或水体。最大房屋检查数仍为 16，其他候选数有上述固定上限，不做无限找地。

生成行为仅用于新世界或原本带有待生成标记的世界。已成功落地的旧测试世界不会自动补盖住宅，避免覆盖玩家后来建设的内容；本次测试请新建世界，保留旧存档。

## 任务书断点与解锁

已对照本地 FTB Quests 2101.1.27 的实际字节码：`BaseQuestFile.readID(String)` 使用 `Long.parseLong(...,16)`，解析失败会分配新 ID。旧脚本直接使用 SHA-256 前 16 位，部分 ID 大于有符号 long 正值上限。例如探索节点 `8464CA606F343573` 和石镐节点 `9991EA50DCDCE562`，在用户运行后的任务文件内分别变成随机 ID `3E4BA3A93004E2E7`、`0D42B0EF16558276`，石镐对探索的依赖已经消失。

固定 ID 现在统一限制到 `0000000000000001` 至 `7FFFFFFFFFFFFFFF` 范围；原来合法的 ID 保持不变。第一章和各节点显式使用 `linear`，依赖方式为 `all_completed`，显示依赖线和锁定图标。全书原先的 `flexible` 默认值及其他五个原型章节不改动。第一章仍是 11 个节点，矿洞后分为生成器和 Create 两路；两路完成才能到维度网络发生器奖励，再连接史莱姆王和邪恶区域开放。

本地 `AdvancementTask` 每隔一段 tick 会检查玩家已保存的进度，因此先做过探索或实际合成、后解锁节点不会仅因错过事件而永久断线。任务图的锁定控制记录/完成任务的顺序，不禁止玩家提前探索或合成物品。实际史莱姆王死亡仍按已批准设计触发全世界邪恶区域解锁，不改写原生 Boss 进度。

游戏曾随机分配的旧 ID 无法直接当成固定 ID 重用。更新不重写旧存档中的 FTB 团队进度；旧测试存档已完成的节点不保证无缝映射，新建测试世界能排除旧进度影响。旧语言键保留，新固定 ID 的标题和描述同步补入语言文件。

## 首次启动错误：已定位报错点，未修复

报告 `crash-2026-10-15_01.30.28-fml.txt` 与同次归档日志最早的阻塞错误一致：Terra Entity 1.2.1 在 `EntityAttributeCreationEvent` 中调用 `TEMonsterEntities.registerEntityAttributes`，访问 `terra_entity:devourer` 时触发 `Trying to access unbound value`。它来自汇流来世 1.2.4 内嵌组件。后面的 Sodium 无法继续加载等错误属于模组加载失败后的结果，不能作为首要修复对象。

崩溃报告使用 Microsoft Java 25.0.1，而项目锁定开发目标为 Java 21。Java 版本差异是后续复现时需要控制的变量，尚不能认定为本次注册失败的原因；第二次能启动也不证明首次错误已经解决。本次不改第三方模组、不升级依赖或修改启动器设置，不宣称启动故障已修复。如果再次报错，保留当次 crash-report 和日志，并记录实际 Java 版本。

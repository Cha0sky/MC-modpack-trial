# 六栋独立地坪与开局赠剑解耦

用户实测：上一版没有任何建筑，原本自动锁定的标准（中等）成长路线又变为可选。用户允许取消统一地坪，但要求六种建筑齐全。回滚起点 `d69fe97`。

## 失败原因

上一版实际日志：第一次49个预览只留下3个候选，全部因保护列被拒；第二次检查8处，7处遇水体/邪恶群系，1处保护列拒绝。整片47×44院落要求过严，最终没有写入建筑。

`ChapterEvents.arrive` 又在没有房屋时直接返回，标准路线和赠剑也因此从未执行。这是建筑生成和开局成长逻辑耦合导致的回归。

仅只读抽查最新失败世界的三个已保存区块：出生点 `(0,64,32)`，出生区块有1个箱子、4个火把（符合原版奖励箱布局），其他区块有水；没有模组植被。未重放生成，不能认定某个箱子是所有候选失败的唯一原因。此次没有放宽箱子/结构保护，改为仅对实际建筑与道路检查，避免把院落空隙也算作施工区域。

## 新实现

- 六个正式 MCP 模板保持原样：新版玩家住宅、两栋村民住宅、水井、农田、扩建空地。每栋独立定高，可有限调整平面位置，以道路相连，不再整平整片院落。
- 新版玩家住宅不可用旧小木屋替代；其后先安排较大的农田，再安排其他四处。六种部件全部规划成功后才放置；缺少农田或主屋，完整性检查拒绝提交，不会跳过任何一处。
- 最多56个主屋纯高度/群系预览、12个实际主屋候选、320次总地块检查；每个部件最多30个候选，削高6格/垫高18格与有界道路沿用既有规则。日志细分拒绝列的坡差、高度、结构、方块实体、具体非天然方块及坐标。
- 标记章节世界登录时先执行标准路线/赠剑，再判断房屋是否存在；登录优先级早于成长武器的普通快照监听。继续使用 `GrowthService.chooseMode` 和幂等 `requestGift`，不手工重复塞剑，不重置已选路线或成长计数。已到达玩家重登不反复切换手持。
- 只有真实房屋生成后才传送进屋、设置床、记录到达与发放“醒来”进度。请求聚落时即启用章节阶段门槛，旧失败 pending 世界登录补激活；未标记的旧世界不改。

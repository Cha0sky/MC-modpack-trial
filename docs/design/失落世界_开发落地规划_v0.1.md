# 失落世界：开发落地规划 V0.1

整理日期：2026-10-11（Asia/Shanghai）。依据：[作者世界观 V1.0](../lore/失落世界_世界观设定_v1.0.md)、[项目 PLAN](../../PLAN.md)、[汇流来世进度调查](../../CONFLUENCE-PROGRESSION-AUDIT.md)。

**本文是开发提案，不是已批准的实施清单或新的正典。** 作者原文中的【已确定】【暂定】【建议】【待定】原样保留；下文新增流程、数据结构、内容例子和里程碑均为【建议】。本次只归档原文、整理方案及更新文档入口，没有制作剧情内容或编写核心模组。

## 1. 开发应该围绕什么展开

【建议】把主线体验组织为：**建立值得守护的生活 → 接触文明遗产 → 挑战腐化守护者 → 解除一处封印 → 获得新的力量与历史线索 → 把成果带回家园**。同一循环逐渐加深，而玩家理解事件的方式在明暗双线中改变。

这样，农业、厨房、女仆、机械工坊和冒险可以相互支撑。遗迹中找到的工艺、材料和记忆应当带回可见的生活成果：改进储存和加工，复原一份食谱，修复一座公共设施，保存一段村史。这些成果说明人类为什么值得继续抗争，也给远征提供实际用途。

“失落世界”目前是世界观与文档的名称，本次没有决定正式整合包发行名、重命名启动器实例或修改已有 mod ID。

## 2. 已确定设定怎样约束实现

| 作者已确定的内容 | 对开发的直接约束 | 初版可以采用的表现方式【建议】 |
|---|---|---|
| 黄金时代机械与魔法属于统一文明 | 技术与魔法的遗迹、术语和历史要能相互解释 | 旧工坊的工程说明与研究日志描述同一设施的不同部分 |
| 世界没有原初意志 | 引导、阶段通知和 NPC 不宣称世界选中了玩家 | 开场来自遗民记忆与旅人行动；阶段提示描述封印变化 |
| 明线不涉及外神 | 开场、普通史书和公共任务介绍不直接解释外神与认知污染 | 明线讲文明成就、灾厄与守护职责；暗线由遗迹记录逐步补全 |
| 求知与黄金时代本身值得尊重 | 研究任务的结论不应变成“一切知识都应禁止” | 记录发现、比对证据与失去控制的过程，保留研究者的理性与努力 |
| 守护者过去的职责有正当性 | Boss 不能只靠“邪恶怪物”介绍支撑主线 | 遭遇前有危险迹象，遭遇后有能解释过去职责的残存证据 |
| 封印同时束缚土地和高阶力量 | 阶段变化应能连接空间、资源与叙事 | 一处危险探索区域、一类资源权限和一组线索共同解锁 |
| 平凡生活也属于文明薪火 | 主线之外需要能持续游玩的生活与建设内容 | 工坊复原、食谱保存、农业设施与同伴生活支线 |
| 主角不登神，薪火属于文明整体 | 成长等级、武器和主线奖励不能被写成玩家私有神权 | 主角帮助已有积累提前显化；文明成就通过多人类证据呈现 |
| 终局延缓污染而非根除外神 | 终幕后的世界仍有探索、危险与发展空间 | 后日谈展现生活改善和新的研究可能，留下尚未解决的区域 |

初版剧情的可战斗对象宜从守护者、异化生物或局部异常中选择；现有高血量 Boss 不直接被定义为“外神本体”。守护者是否是原始英雄、继任者或造物，仍按作者标记保持待定。

## 3. 叙事幕次、世界阶段和玩家发现应分开

作者提出的五幕是【建议】叙事结构；PLAN 中 4–6 个大阶段也是待选规模。**不能据此提前把核心写死为五个阶段或五位守护者。**

【建议】采用三类状态：

| 状态 | 作用范围 | 例子 | 应由谁维护 |
|---|---|---|---|
| 世界进度 | 世界共享 | 某处封印已解除、某资源组已开放 | 世界进度核心，作为权限依据 |
| 玩家发现 | 玩家各自记录 | 是否读过一份手稿、是否找到某段守护者记忆 | 玩家发现记录与任务/档案展示 |
| 文明实践 | 支线内容与场景反馈 | 修复工坊、保存食谱、整理史料、完善家园 | 任务内容或具体互动，初版可用已有系统承载 |

这能支持多人和半开放探索：一人完成关键守护者后，全世界获得阶段变化；晚加入的玩家可以追溯已经发生的事件，同时保留自己尚未读过的线索。提前找到暗线碎片的玩家可以保存发现，不因故事章节尚未推进而被强制删除成果。

“文明实践”初版不必变成统一数值条。玩家做过哪些有意义的事情可以通过具体作品、档案和支线完成记录体现，避免把薪火主题变成反复刷作物或杀怪积攒的分数。

## 4. 建议先完成的第一段可玩流程

以下是**工作用流程**，不是正式开场台词、关卡地图、守护者身份或最终章节名。先验证一段体验，之后再讨论扩展规模。

| 环节 | 玩家具体行动【建议】 | 叙事作用 | 第一版的实现范围 |
|---|---|---|---|
| 安家 | 准备食物、住所与基础储存，自选一处家园 | 让玩家先拥有值得保护的生活 | 用现有生活系统和任务文本，不强制建造指定房型 |
| 认识遗产 | 从一份旧工坊资料得知遗民仍在使用残存技术 | 展现文明持续创造，而非只剩废墟 | 一份简短明线记录及一个可完成的基础生产目标 |
| 主动远征 | 按线索找到一处小型遗迹或待修复设施 | 将家园需求连接到探索 | 先确定一种可复用的遗迹载体，不预设大型世界生成工程 |
| 发现异常 | 取得一份有明确用途的旧日志，并看到局部装置异常 | 引入暗线疑问，保留解释空间 | 只交付一条新信息；外神机制与界外身份保持在后续叙事位置 |
| 挑战守护者 | 准备装备，挑战第一位具体选定的根 Boss | 让解除封印成为有分量的行动 | Boss 选型后绑定实体 ID，处理部件、重复击杀与多人共享 |
| 解封反馈 | 看见一类资源/权限开放，并取得说明其历史的片段 | 同时给出建设机会与新的疑问 | 先开放一种真实内容，污染数值和全局生态改造放到后续独立任务 |
| 带回家园 | 用新材料改进一个生产或生活环节 | 让冒险成果转化为文明延续 | 完成一项可见的用途，形成“需要—探索—获得—应用”的闭环 |

第一段无需预先制作完整 NPC 城镇。开场可由任务书、玩家营地与少量可读资料承载；定制聚落、对话角色和大型遗迹作为后续内容层逐项加入。女仆与休闲支线在早期保持可选，不作为第一位守护者的强制战斗前置。

### 第一位守护者的选型表

在确定具体模组 Boss 前，先填完这张表，再查实际实体与战斗行为：

| 必填内容 | 需要回答的问题 |
|---|---|
| 封印职责 | 它保护过什么土地或力量？ |
| 历史证据 | 玩家能从什么遗物理解它的过去？ |
| 当前危险 | 扭曲如何影响当下的遗民与探索者？ |
| 战后解锁 | 一种什么资源或功能足以改变早期玩法？ |
| 信息推进 | 战前和战后各新增哪一条认知，哪些仍应留白？ |
| 生活用途 | 新资源带回家园后实际能做什么？ |
| 技术边界 | 根实体/多部件、召唤路径、重复击杀和原生世界变化有什么限制？ |

灾变、汇流来世等先作为内容素材库，现有 Boss 的背景与最终战力不能反过来决定正典。当前不指定某个 Boss 就是古代英雄，也不指定终幕 Boss 等于外神。

## 5. 世界进度核心的实现顺序

### 第一步：独立进度底座【建议】

保留此前 MVP 的保存、可配置 Boss 映射、命令、一次性通知与查询接口，同时让配置能表达封印和解锁权限。

| 数据 | 含义 | 第一版边界 |
|---|---|---|
| `schema_version` | 存档结构版本 | 为后续迁移保留入口 |
| `completed_milestones` | 已确认的关键通关 | 重复击杀不重复晋级或发奖 |
| `released_seals` | 已解除的封印 ID | 先只有未解除/已解除，接管与稳定机制仍待定 |
| `unlocked_rules` | 已开放的资源/功能组 | 普通生活规则默认开放，关键内容显式配置 |
| 阶段显示信息 | 当前变化的玩家提示 | 玩家可见文本按明线叙事写，不在初期暴露设定真相 |

这些是结构建议，不预定正式 ID、阶段名称或数量。第一版可用明确标注的测试配置证明保存和幂等，正式守护者绑定等内容设计后替换。

### 第二步：一项真实资源联动【建议】

选择一种阶段资源，打通“击败守护者 → 世界记录更新 → 获得样本机会 → 用于生产”的路径。资源生成模组可以承担获得样本之后的稳定供应，减少重复挖矿。

阶段检查应同时覆盖模板制作与实际产出，并核对合成、战利品、交易和自动化等实际来源。将 Boss 独有凭证与可批量供应的普通原料分开，是需要单独确认的资源策略。已有模板、他人转交的样本或旧存档物品也需要纳入验证。

“先探索获得样本再自动化”在作者原文中是【建议】，本提案保留为候选，不改变当前无限之核配方或接口。

### 第三步：档案与发现记录【建议】

世界阶段负责哪些内容开放，玩家档案负责玩家已经理解哪些事实。线索先有稳定 ID、来源和可见文本，再讨论复杂的拼合 UI。

第一版可以记录一份手稿和一份战后记忆的发现；多人分别记录阅读状态，但都能查看世界已解除的封印。任务书从核心读取阶段结果，用于引导和展示；玩家拥有某件可复制物品，不应成为关键守护者已经通关的唯一证据。

### 第四步：Retrogen 与局部世界反馈【建议】

先选一种独立测试矿物实现旧区块追加，再逐步设计正式清单。每区块记录处理批次，使用限额调度与明确替换规则，先在另行批准的测试存档中验证。

矿物显现可以表现为被束缚力量重新进入现实。保护玩家已有建筑、并与汇流原生隐藏矿分工，是实现边界；普通石头是否由玩家放置无法仅凭方块类型可靠判断。

污染相关的刷新、传播、侵蚀值或全局异常事件尚待创作和玩法决定。第一段体验可通过局部遗迹、敌人和记录表现危险，避免尚未确定系统就把日常生产与阅读变成持续惩罚。

## 6. 明暗线内容的制作规范

【建议】每条内容登记以下信息，便于后续审稿与联动：

| 字段 | 用途 |
|---|---|
| 内容 ID、载体与位置 | 追踪一段文字来自谁、在哪里出现 |
| `main` / `hidden` | 标注明线或暗线，不由文件名暗自决定 |
| 信息来源的知识边界 | 遗民口述、工程记录、个人记忆分别能知道什么 |
| 新增认知与仍未解释的问题 | 避免每份日志重复同一段背景，或一次给出全部答案 |
| 展示位置 | 检查任务标题、HUD、物品名与正文是否提前泄露 |
| 发现方式与解释条件 | 用于半开放探索和晚加入玩家的追溯，不把所有碎片强制章节锁死 |
| 正典状态与原文出处 | 保留作者的确认/建议/待定边界 |

初期明线资料应具体展示文明成果和幸存者生活：某座设施解决过什么问题，工匠保存过什么经验，灾厄时人们保护过什么。暗线则从可理解的研究记录出现异常，逐步引出认识失效与封印抉择。单纯重复“低语、疯狂、不可名状”不足以替代历史证据。

第一段暗线日志只需提出一个问题，例如装置实际工作与维护记录出现了无法解释的矛盾；具体设施、研究事件和术语仍待作者确认。主角的界外映射属于后期揭示范围，开场引导不应直接解释玩家在现实中操控角色。

作者设定集是面向开发者的完整参考资料。玩家可读内容应单独编写与审阅，保留不同载体的知识边界，不把设定全集直接当作开场书籍。

## 7. 生活内容怎样承担主题

以下是支线类型示例，均为【建议】，不是已经写好的正式任务：

- **保存一份食谱**：找到残缺的家庭记录，用当地食材复原，让历史落到厨房与日常。
- **修复一段生产链**：恢复旧工坊的一项实际能力，再改善玩家自己的生活设施。
- **留下可传承的农事经验**：把探索所得材料用于农业或加工，并完成一份可读记录。
- **完善同伴的生活空间**：厨房、居所、庭院与休闲区域让家园成为远征之后的归处。
- **保存一段普通人的历史**：拼合账册、维修单、书信等，让黄金时代包含普通人的劳动。

这些支线应有独立价值，供玩家选择。文明整体的薪火通过具体人的实践和记录体现，避免把所有农耕、居所建设或女仆活动都变成推进 Boss 章的必做清单。

角色加点和成长武器提供个人成长；它们与世界阶段、文明贡献分别设计，保留其他装备路线的使用价值。薪火的孕育、提前显化和未来神性可能是正典关系，不应未经设计就等同于三个技能等级或一把武器的升级条。

## 8. 汇流来世：需要先确定的分界点

此前只读调查确认，当前汇流版本的肉山/血肉之丘死亡会启动原生困难模式变化，转换后事件不能提前取消；祭坛显现矿物也有独立路径。因此，原创封印进度不能只靠任务书重命名就获得严格控制。

【建议】在正式 Boss 选型时比较两条路线：

1. **将原生分界点纳入封印设计**：决定肉山与血肉之丘是否承担同一处封印职责，并核查全部正常触发路径。如果它是主线关键门槛，提前召唤和原生资源解锁需要按批准的设计处理。
2. **限定原生世界变化的作用空间**：调查将汇流内容安排在远征区域/独立维度的实际可行性，评估相关附属与当前版本的匹配；角色返回固定家园时仍有安定生活空间。维度分离也不自动等于共享进度隔离。

两者均未定案。世界进度核心先拥有自己的保存和权限接口；是否单向读取原生记录、是否增加入口门槛，随后根据实际关卡选型决定。不能直接用有副作用的原生阶段 setter 逐刻对齐原创阶段。

## 9. 开发顺序与每项交付

| 顺序 | 任务提案 | 可审阅交付 | 完成标准 |
|---|---|---|---|
| A | 第一段主线规格 | 开场、第一处封印、战前/战后线索、一个解锁用途与候选 Boss 评估表 | 正典出处清楚，未定项列明，能确定第一段制作范围 |
| B | 世界进度核心 MVP | 独立源码、测试配置、保存与查询/命令/通知、必要验证记录 | 测试通关幂等，保存数据有明确结构；代码与游戏验证分开报告 |
| C | 第一段玩家内容 | 少量任务、线索与一个可用资源联动 | 玩家能完成一次家园—远征—解封—应用循环，信息没有越过载体知识边界 |
| D | 一种矿物追溯生成 | 分批队列、处理记录、保护规则与恢复证据 | 新旧区块按规则获得矿物，重复加载与中断不重复生成 |
| E | 扩展主线及终幕后反馈 | 正式守护者与区域、资料、世界变化、生活支线 | 基于实际体验逐段扩展，终幕体现显著延缓而非根除污染 |

故事规格与通用核心设计可以相互校对，但每项实施都要单独说明范围并得到用户同意。当前尚未批准上述 A–E 的制作或代码实施。

### 建议下一项任务

先制作 **《第一段主线规格 V0.1》**，只完成开场体验、第一处封印的职责、一组明暗线索、一种解锁用途与 Boss 候选评价。涉及新的名字、角色历史与具体守护者绑定时保留候选标记，交由用户确认；暂不制作任务书、安装模组或修改实例。

拿到这一页关卡规格后，世界进度核心的第一项测试才有明确服务对象，后续逐项实现也能用同一段流程验收。用户若希望优先做通用技术底座，也可沿此前 MVP 范围先实现，不据此擅自定案剧情。

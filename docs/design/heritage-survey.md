# 第二章 · 遗产调查

更新：2026-11-16。当前状态：**已部署，待用户实机验收**；最终编译和部署状态由本轮交付记录更新。第一章[重启第一座工坊](workshop-rekindled.md)也仍待用户实机验收，不将代码完成视为游戏内通过。

本章承接旧工坊恢复后的工艺记录。工程、奥术、远征三条路线可以自由安排，**完成任意两条即可汇合并使用遗产档案台**；第三条保留可选奖励。路线完成事实按世界共享，允许同伴分工和后加入玩家接续。这里只写功能与玩家指引，不把模组原有背景提升为正式剧情。

| 节点 | 玩家目标 | 后续 |

## 工程路线

热工需要真正装入烈焰人的燃烧室，空燃烧室不计入。黄铜、机械手、注液器和精密构件沿用 Create 原生体系；普通熔炉与第一章加工仍然可用。

装配节点要求机械手实际工作、注液器完成一次有效注液，以及取得精密构件。可以用注液器向玻璃瓶注入 250 mB 蜂蜜。精密构件沿用五轮机械手装配的原生配方，成功率为 80%。

工程记录奖励包括黄铜锭、传动杆、机械臂、黄铜漏斗、传送带和铁板。

## 奥术路线：任选一种实践

| 体系 | 基础准备 | 实际实践 |
|---|---|---|
| Iron's Spellbooks | 铭文台、铁质法术书，并实际装备法术书 | 使用法术书成功释放一次法术 |
| Goety | 取得黑暗魔杖 | 召唤僵尸仆从，并让仆从击杀一个敌人 |

任选铁魔法或诡厄巫法，在同一个体系内完成基础与实际操作即可登记奥术路线。

奥术记录奖励包括附魔台、16 个书架、纸、青金石和经验瓶。

## 远征路线

调查要求两种不同的结构类型，反复进入同一类型不增加种类数：

| 结构 ID | 玩家指引 |
|---|---|
| `mowziesmobs:wrought_chamber` | 钢铁守护者的地下房间；结构选址还受模组配置影响 |
| `confluence:enchanted_sword_shrine` | 附魔剑冢，分布于多种主世界群系的地下 |
| `cataclysm:desert_site` | 沙漠遗址，可能遇到普通守卫 |
| `cataclysm:ancient_factory` | 古代工厂，地下调查；本章不要求击败工厂中的大型首领 |

以下挑战任选其一：

- `mowziesmobs:ferrous_wroughtnaut`：钢铁守护者。第一章相关支线已完成时可承认原有记录。
- `mowziesmobs:frostmaw`：霜冻巨兽。
- `terra_entity:eye_of_cthulhu`：克苏鲁之眼。
- `terra_entity:eater_of_worlds`：世界吞噬怪。
- `terra_entity:brain_of_cthulhu`：克苏鲁之脑。
- `goety:skull_lord`：诡厄巫法的骷髅领主，可在大坟墓 `goety:crypt` 开罐时遭遇。已取得原生击败成就也能计入。

判定使用首领本体的有效击败，玩家可按照装备与补给选择挑战。

远征记录奖励包括保护Ⅲ／摔落保护Ⅳ／耐久Ⅱ钻石靴、末影珍珠、经验瓶、金胡萝卜和箭矢。

## 遗产档案台

自选委托「地图上墙」需要把档案台绘出的遗址地图放进普通或荧光展示框。队友可以直接对着图上的标记认路。

工作台配方：

```text
B G B
C A C
P R P
```

- B＝书，G＝玻璃，C＝铜板。
- A＝安山机壳，P＝木板，R＝第一章共振胶。
- 合计需要书×2、玻璃×1、铜板×2、安山机壳×1、木板×2、共振胶×1。共振胶可使用恢复旧工坊时领取的补给。

配方不使用黄铜，因此选择“奥术＋远征”的玩家也能正常完成共同收尾。

完成任意两条路线后：

| 操作 | 实际作用 |
|---|---|
| 普通右键 | 首次免费获得档案书；已有档案书时更新其中的路线与地点记录 |
| 持普通书右键 | 档案书遗失后补领，消耗一本普通书 |
| 潜行右键 | 切换当前选中的已记录地点 |
| 持空地图右键 | 将当前记录的地点绘制成地图 |

地点来自玩家**已经发现**的上述四种调查遗迹，或 Explorify 的各结构类型首次发现位置。档案台不搜索或凭空提供未知结构坐标，也不要求为此生成一片新区域。同类地点保留首次记录，用于回访和整理远征经历。

两线汇合后可领取各 128 个石砖、平滑石头和原木。首次打开档案可领取 8 个物品保险库、效率Ⅳ／耐久Ⅲ钻石斧、金胡萝卜、展示框和灯笼。

三线全部完成额外获得修补书×1、钻石×8、经验瓶×32，还可从物品保险库×4、金苹果×4、经验瓶×24 中选一项。

## 本轮边界与玩家验收

本轮不新增大型结构或模组，不触发或改写汇流来世困难模式，不重写正式世界观。沿用第一章与现有世界进度，保留玩家在其他路线中的成果。

## 实施记录

核心构建标识 `0.3.0-heritage`。Java 21 离线 `build` 与 `verifyLogic` 通过，相关检查覆盖三种两线组合、重复同路线不计第二线、奥术同一体系闭环、首领根实体及地点归类。生成器检查14节点、跨章依赖、任选两线与奖励；未运行游戏、服务器、GameTest或文件哈希。

本章只新增档案台方块，不新增模组或世界结构。当前 Iron’s Spellbooks 3.16.3 JAR 复制到 `staging/mods` 供仅编译依赖，监听其实际法术书释放事件；此事件证明释放动作，不表示后续投射物必然命中。原生精密构件持有进度可承认此前成果。已有世界路线同步时，会同时补齐对应路线前两个节点，避免后来玩家被FTB前置锁住。

构建沿用现有JDK/SDK与 `-Pmod_version=0.3.0-heritage build -x createMinecraftArtifacts`。`tools/build_heritage_quests.py` 管本章数据，`HeritageEvents` 管玩家事实，`HeritageWorldData` 管共享记录，`HeritageArchive` 管书与地图；`tools/deploy_heritage.py` 只更新核心、新章节和两份合并语言。

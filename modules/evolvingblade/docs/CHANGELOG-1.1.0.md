## 1. 第三方加伤：（真实结算 / 显示）分开处理

### 1.1 先诊断，再修

用户反馈的“吃不到加伤”经核实是**面板没有变化**，并未确认实际近战伤害没有加成。
这次按“先复现对比、再改”的顺序做了三件事：

1. 只读分析了 mod test 实例里的第三方模组：
   - `rpgleveling-1.0.0.jar`：`com.rpgleveling.stat.AttributeApplier` 直接对
     **原版 `minecraft:attack_damage`** 施加修饰符，id 形如
     `rpgleveling:<stat>`（`AttributeApplier` 里 `ResourceLocation.fromNamespaceAndPath("rpgleveling", stat.id())`）。
     Codex 独立 `javap` 实证的字节码分支是：
     `Mode.FLAT` → **`ADD_VALUE`**；
     `Basis.TOTAL` → **`ADD_MULTIPLIED_BASE`**（<b>不是</b> `ADD_MULTIPLIED_TOTAL`——
     早先这条记录有误，已按字节码更正）；
     另有"设计基线"分支同样落地为 `ADD_VALUE`。
     也就是说三种原版标准操作它都会用到，本模组**不需要**、也**不应该**硬绑定到某一个模组；
     我们只保证"自己的差值不读 `getValue()`、不减 base、不减第三方 ADD"，
     于是三种操作都能自然叠加。
     它**不注册**自己的攻击属性（`RpgAttributes` 里只有 xp_gain / drop_rate / lifesteal /
     crit_damage / crit_chance / damage_reduction / health_regen）。
     它**不注册**自己的攻击属性（`RpgAttributes` 里只有 xp_gain / drop_rate / lifesteal /
     crit_damage / crit_chance / damage_reduction / health_regen）。
   - `无限之核模组-infinitecore-1.0.0.jar`：`com.infinite.core.*` 只有发电机 / 模板 / 配方与菜单，
     **不触碰攻击属性，也不订阅伤害事件**（与加伤无关，记录在此以免再被误当成来源）。
2. 因此把问题拆成两条独立路径分别验证：
   - **真实结算**（近战直击）：走原版 `Player.attack → getAttributeValue(ATTACK_DAMAGE)`，
     只要属性管线正常就一定吃到加伤；
   - **显示**：`EBPayloads.snapshotFor` 曾把 `settings.stageAttackDamage(stage)` 直接下发，
     面板/提示框永远是“阶段配置值”，所以第三方加伤**在面板上永远看不到**——这就是用户看到的现象。
3. 技能路径（剑气 / 爆发）确实是**真的**没吃到：`CombatMath.waveDamage/burstDamage` 只取阶段配置，
   完全不读持有者有效攻击。这一条属于真实功能缺口，1.1.0 修掉。

### 1.2 不再写入原版保留槽位（消除“抹掉别人修饰符”的结构性风险）

`StageAttributes.ensureBaseline` 曾每次协调都把玩家身上
`minecraft:base_attack_damage` / `minecraft:base_attack_speed` **强制改写回物品基线值**。
原版 `LivingEntity.collectEquipmentChanges`（装备 tick）自己就会对这两个 id 做
`removeModifier(id)` + `addTransientModifier(id)`，我们再去抢写只会让
“第三方用同一个保留 id 提出的合法修改”被更早、更频繁地覆盖。

现在：

- 本模组**永不写入**这两个保留 id，也永不触碰任何第三方 id；
- 阶段增量相对**物品出厂阶段 0（7.0 / 1.6）**计算：
  `stageDelta = 配置该阶段绝对值 − 7.0`。
  **每个阶段的绝对配置值各自生效**：只把 stage0 从 7 改成 12，就只有阶段 0 变成 12，
  终阶仍是配置里的 1500。（早先"改 stage0 会让全部阶段整体平移"的说法是错的，已更正。）
- 差值**不读** `AttributeInstance.getValue()`、**不减** `getBaseValue()`、
  **不减**任何第三方 `ADD_VALUE`；"把别人已经乘过的结果减成 ADD 导致乘法重复"这条路径结构上不存在；
- 保留槽位不是当前物品的结果时（缺失，或还留着上一把武器的值），
  用<b>本模组独立的 id</b>（`evolvingblade:baseline_attack_damage` /
  `baseline_attack_speed`）补 `声明值 − 观测值` 这份缺口，
  与阶段增量分开记账——所以阶段 0 可以完全没有阶段增量修饰符；
- 补偿是**幂等**的：只有当观测到的保留槽位确实等于当前物品声明值时才撤销；
  一直缺席或一直是旧武器的值就维持同一份补偿（旧实现"读一次就当第三方改动"会吃掉补偿）；
- 攻击与攻速**各自独立记账**（旧实现共用一个 UUID 集合，会让攻速补偿被误清）；
- 本模组不做反射、不引入 Mixin（原版 `getLastHandItem` / `lastItemInMainHand` 都是 private，
  不存在可用的公共"上一把武器"API），改用"槽位值是否等于当前物品声明值"这一可核实判据。

### 1.3 技能伤害改为按持有者服务端有效攻击取值

新增配置 `abilities.ability_damage_from_attack`（**默认 `true`**）：

```
继承开启（默认）：技能伤害 = 系数 × 服务端有效持剑 ATTACK_DAMAGE
继承关闭        ：技能伤害 = 系数 × 阶段配置基础攻击（1.0.0 行为）
```

- 系数沿用原值：剑气 `1.0`、爆发 `1.5`；它们是**比例，不是阶段天花板**——
  正的加伤必须真的增强技能（阶段 3 有效 1000 → 剑气 1000；阶段 4 有效 1000 → 爆发 1500）；
- 配置 `false` 时完全回到 1.0.0 的"只看阶段配置"口径，面板会明确提示已关闭；
- 非法/非正的有效攻击（NaN、负数、无属性）一律回落到阶段基础值，绝不产生 NaN 伤害；
- 只保留**防御性绝对上限** 8192（原版 `RangedAttribute` 已把 ATTACK_DAMAGE 钳在 **2048**，
  这才是真实约束；本模组**不修改**这个全局上限，也不承诺任何绕过它的第三方模组）；
- 施法前会先把持有者属性协调到当前阶段（`StarEaterAbilities.ready()`），
  否则会读到裸 base；被拒绝的施法不消耗冷却、也不改动任何属性状态。

原版伤害管线仍然只执行一次第三方倍率：技能只是普通 `hurt()`，
免疫 / 取消 / 受击冷却照旧生效，不伪造近战事件、不额外 `setHealth`、不触发吸血 / 弑王递归。

### 1.4 面板与物品提示框分开显示两个口径

服务器权威快照新增三个字段：

| 字段 | 含义 |
|---|---|
| `stageBaseAttack` | **阶段基础攻击**：配置里该阶段的总攻击，只是系数口径，**不是**玩家真实伤害 |
| `effectiveHeldAttack` | **当前持剑有效攻击**：服务器读到的 `ATTACK_DAMAGE` 最终值（含标准属性 base、物品基线、第三方 flat 与百分比，已被原版钳到 2048） |
| `holdingStarEater` | 当前是否**真的主手**持着本剑 |

- **只在真的主手持剑时**下发有效攻击；未持剑时下发 `NaN`，UI 显示“未持剑”，
  预览背包里的剑**不会借用别的武器的加成**；
- 两个口径在仪表盘与提示框里各占一行，并明确写出
  “有效攻击＝属性表上的攻击力，实际伤害仍受附魔、目标护甲与事件影响”；
- 网络仍是有界的：快照本来就只在登录 / 重生 / 换维度 / 选择 / 升级 / 冷却中或持剑时约 1 秒一次；
  这次只在**已有**的快照里加了 3 个定长字段，没有新增周期性广播。
- **协议版本从 `"1"` 升到 `"2"`**：字段布局与新增载荷都变了，旧客户端/服务端不再互认。
  **存档兼容 ≠ 网络协议兼容：双方必须是同一版本。**

## 2. 爆发的三维球判定（这次是判定本身，不只是粒子）

1.0.0 的爆发用 `player.getBoundingBox().inflate(r)` 取候选 + `distanceToSqr(player)`（脚底）
排序，粒子画在地面圆环上。1.1.0 明确为三维球：

- **球心**＝施法者躯干中心 `(x, y + bbHeight/2, z)`；
- **半径**＝配置的 6（终阶 8），三轴都参与；
- **命中判据**＝目标**包围盒**到球心的最近点距离平方**严格 ≤ r²**
  （`EffectiveDamage.sphereIntersectsAabb`，三轴各取最近投影）；
- 粗筛包围盒额外放宽 16 格（`BURST_BROAD_PHASE_MARGIN`），保证末影龙级别的大型包围盒
  不会在粗筛阶段就被丢掉；精确判定仍按最近点距离；
- 排序键改用“最近点距离”，与命中判据同口径，于是“最近优先”与“贴边可命中”一致。

因此正上方 / 正下方 / 空中的目标都能命中，贴边的大型实体也能命中，
而 X/Z 圆柱或“只算脚底距离”会漏掉这些情况。

仍然保留：`cap 32`、视线（LOS）、队友 / 玩家 / **一切被驯服或有主人**的生物排除、不破坏方块。

## 3. 视觉整体重实现（客户端铺开 + 有界广播）

旧的实现是“服务器逐点 `sendParticles`”：剑气沿射线撒 SWEEP_ATTACK、爆发画 48 个地面圆环、
弑王用 FLASH、爆炸音效。这既不三维，也会产生大量独立粒子包。

1.1.0 改为**一个施法事件一个包**：

- 新增 S2C 载荷 `evolvingblade:ability_effect`（`AbilityEffectPayload`），
  只携带视觉参数（种类 / 原点 / 方向 / 幅度 / 阶段档），**不含任何权威数值**；
- 只发给同维度且距离 ≤ 64 格的观察玩家（`MAX_VIEW_DISTANCE`），距离外**收不到包**；
- 客户端 `EBAbilityClient` 在自己的 tick 里铺开粒子脚本，全部使用
  **客户端本地粒子**（`Level.addParticle`），网络侧与粒子数量无关；
- 硬上限：同屏活动效果 ≤ 12、每 tick 生成 ≤ 24 个粒子、单效果寿命
  剑气 10 tick / 爆发 20 tick / 吸血 8 tick、单效果粒子预算 64 并随
  **原版“粒子效果”选项**降级（减少 ×0.55、最少 ×0.25，最少档还会跳过星轨层）；
- 换维度 / 死亡 / 断线时清空。

各效果：

| 效果 | 实现要点 |
|---|---|
| 爆发 | 约 14–20 tick 从**躯干**扩张到真实半径的**三维球壳**（黄金角稀疏分布，内部为空，不是实心球），青白内核 + 三组不同倾角的稀疏紫色星轨（终阶只多一组、提高亮度，不增数量级） |
| 剑气 | 细长弯月刀光沿**真实被墙截断的 reach** 前进（服务器把截断后的距离下发，客户端不可能画得比判定远），短拖尾 + 少量星尘 |
| 命中 | 紧凑交叉星芒（2–4 条臂） |
| 弑王 | 目标附近的**小型紫金斩痕**（斜十字，少量点） |
| 吸血 | 少量从目标向施法者运动的点（`ParticleTypes.ENCHANT`） |

爆炸音效已移除（改为克制的挥砍音），不调用任何爆炸、不改变方块。
所有 client 类只在客户端加载（`@Mod(dist = CLIENT)` 与 `FMLEnvironment.dist.isClient()` 双重保护）。

## 8. 特效几何与渲染坐标（本轮修正）

- **渲染坐标（严重缺陷）**：一手核实 `GameRenderer` 构造的 `frustumMatrix` 只有**旋转**
  （`new Matrix4f().rotation(camera.rotation().conjugate())`），`AFTER_PARTICLES` 时
  `posestack` 仍是**单位矩阵**，`modelViewStack` 的 pop 在更后面。
  所以顶点必须先在 CPU 侧**减去相机位置**，再由 modelView 做那一次旋转；
  旧实现直接提交世界坐标，特效会飘到世界原点附近。纯数学在
  `AbilityGeometry.cameraRelative / applyRotation3x3`，并有单测保证
  "相机平移 1000 格相对顶点不变"与"旋转只应用一次"。
- **剑气**：改为在**垂直于射线**的平面（`side × up`）上画短弧刃
  （半径 0.7 格 → 直径约 1.4 格、厚度 0.08 格），从 **0.7 格**处沿射线移动到真实截断点。
  旧实现把弧铺在"射线方向 × 侧向"平面里，第一人称几乎 edge-on 看不见。
  单测断言弧平面法线与射线**平行**、弧上每点到射线轴距离恒等于弧半径。
- **爆发**：三条弧的相位由 `burstArcPhase` 给出，每条**跨过 y 零点**并在**不同倾角 +
  不同方位角**上展开，因此画面**上下都有**弧线段（旧实现三条全在上半球）；
  弧带厚度固定 0.04…0.09 格（旧实现 0.055×r 在 r=8 时达 0.44，像粗管）；
  **不随 age 旋转**，是一次安静的脉冲。单测用**真实渲染相位**取点，断言 relativeY 含正负、
  最大距离恰等于真实半径、三条弧的参数两两不同。

## 9. 测试与真实事件顺序（本轮修正）

- `SourceFactGameTests.underchargedFollowUpGivesNoStaleLifesteal`：

  本模组的缺席补偿不会被重新评估（实测 `attackSpeed=0`）。测试现在在 doTick 之后显式调用
  `GrowthService.syncAfterChange` 复现真实服务器调度；**没有**修改 attackSpeed 或任何数值，
  满蓄力回血 / 同 tick 追击不回血的断言全部保留。
- `AttributeMathGameTests.stageZeroRemovesOnlyOurModifierAndKeepsBaseline`：
  拆成"装备 tick 之前"（本模组独立补偿 id 存在、阶段增量为 0）与"装备 tick 之后"
  （原版保留槽位存在且等于物品声明值、本模组 delta 与补偿都已清除）。
- `ThirdPartyDamageGameTests.standardAttributeBonusAndMultiplierChangeRealAbilityDamage`：
  改用**阶段 4（裂空，基础 120）**而不是终阶——原版把 `ATTACK_DAMAGE` 钳在 **2048**，
  终阶 1513×1.5=2269.5 会被钳制，测不出"技能跟随有效攻击"。现在断言
  有效 133 → 剑气**真实掉血 133**、×1.5 后 199.5 → 爆发**真实掉血 299.25**，
  并显式 `setYRot/setXRot` 对准目标（断言方向 dot > 0.999、LOS 通畅），
  同时保留"原版上限 2048"的事实检查。

## 7. 特效收敛为 MC 可读像素/分段轮廓

- 剑气：**一条清楚的短青/靛紫弧刃**（长约 1.9 格、半宽约 0.11 格、轻微外凸）
  + **极短稀疏尾迹**，沿**真实射线**（被墙截断后的 reach）移动；不是团圆盘、不是满屏长条。
- 范围爆发：以**真实范围中心**发出**一次约 14 tick** 的稀疏三维脉冲——
  三条**不同平面的分段弧**（张角约 150°，倾角 1.45/0.95/0.50 弧度，其中一条接近竖直 →
